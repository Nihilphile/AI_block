# Module or Boundary Review

1. Confirm exact implementation subject, comparison baseline, evidence baseline, and current orchestration HEAD.
2. Read only loaded design, authority, evidence, and gate context.
3. Review semantics, ownership, Contract compatibility, failure behavior, security/trust boundary when active, and phase scope.
4. Lead with actionable findings ordered by consequence.
5. If none exist, say so explicitly.
6. Separate defects, evidence gaps, and deliberately deferred risk.
7. Give a clear acceptance or remediation recommendation.
